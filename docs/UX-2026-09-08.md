# Fluidez de reservas y carga por página

Mejoras del 8 de septiembre de 2026 incluidas en el PR #11. El titular ha autorizado
fusionarlas y publicarlas. El estado del despliegue se registra en
[HOSTING_ALWAYSDATA.md](HOSTING_ALWAYSDATA.md).
No cambian tarifas, textos legales ni credenciales. No incorporan servicios
externos o dependencias nuevas.

## Recorrido de reserva

- Cambiar ES/EN/EU conserva el alojamiento, las fechas y adultos, niños y mascotas
  elegidos en ese momento. Los enlaces incluyen exclusivamente esos criterios.
  Nombre, correo, teléfono, mensaje y consentimiento no se transfieren ni se
  guardan en `localStorage` o `sessionStorage`.
- En móvil, el total estimado y un botón «Continuar» permanecen accesibles cuando
  el botón final está lejos. El botón lleva al primer campo obligatorio pendiente,
  no envía una solicitud. El resumen se retira al escribir, abrir un diálogo,
  acercarse al envío final o completar la solicitud. WhatsApp ocupa menos espacio.
- Los botones de adultos y niños respetan la capacidad conjunta. Cambiar a un
  alojamiento más pequeño no elimina huéspedes silenciosamente: muestra un aviso
  junto a los campos y permite reducirlos.
- El calendario avisa mientras consulta y ofrece reintentar si falla. Conserva
  los últimos bloqueos conocidos, nunca convierte un fallo en una disponibilidad
  confirmada. Consulta solo el alojamiento seleccionado y reutiliza la respuesta
  durante un minuto; al reabrir o volver a la pestaña refresca si está caducada.
- Los fallos temporales del servicio pueden recuperarse sin recargar ni perder
  los campos escritos. Una respuesta de conflicto fuerza a actualizar las fechas.
  La API continúa comprobando fechas y precio al enviar, y la confirmación evita
  solapamientos de forma transaccional.

## Rendimiento

Primera medición de los archivos propios sin comprimir, frente al commit `4f9125d`
(la precarga de galería posterior añade 510 bytes al script común):

| Recorrido                              |        Antes |        Ahora |
| -------------------------------------- | -----------: | -----------: |
| Páginas informativas: JavaScript total | 31.196 bytes |  4.728 bytes |
| Reserva: JavaScript total              | 31.196 bytes | 37.903 bytes |

Las páginas informativas cargan un 85 % menos de JavaScript. Esto no significa
que el tiempo de carga total mejore un 85 %: también depende de imágenes, red y
dispositivo. La reserva incorpora los avisos y mejoras descritos; su código y el
motor de tarifas solo se cargan allí, con scripts diferidos y nombres con hash.

Los cambios de huéspedes reutilizan los nodos del calendario y el formateador de
moneda. No se consulta disponibilidad al pulsar cada contador. Los tests fijan
presupuestos de 7 KB de JavaScript informativo y 42 KB en reserva para detectar
regresiones accidentales.

### Segunda optimización

- Brotli y gzip se generan durante la compilación con las funciones de Node,
  sin comprimir en cada visita ni añadir dependencias. El servidor negocia la
  variante admitida por el navegador y mantiene tipos MIME, ETag, HEAD y caché
  inmutable para los recursos con hash. HTML sigue revalidándose.
- API y gestión permanecen fuera de esta compresión y con `no-store`.
  Las variantes internas no son rutas públicas; se retiran al reconstruir para
  no conservar borradores retirados. Si falta una variante se sirve el original.
- La galería anticipa una única foto siguiente al abrirse o avanzar; no inicia
  esas descargas al visitar la página. Respeta ahorro de datos y conexiones 2G
  cuando el navegador informa de ellos, y usa prioridad baja.

Ejemplos del build de revisión: portada HTML 14.587 → 3.740 bytes, CSS
56.285 → 10.012 bytes, script común 5.238 → 1.512 bytes con Brotli. Los originales
no se alteran. Las páginas publicadas conservan la privacidad anterior y su
tamaño HTML puede variar ligeramente. No se trata de una puntuación Lighthouse.

- `PLAYWRIGHT_CHROME_CHANNEL=chrome npm run test:browser`: 9 pruebas, incluidos
  cinco recorridos nuevos dentro del escenario de UX. Base de datos en memoria,
  correos desactivados y datos ficticios.
- Navegación, galería, envío y gestión existentes conservados; recorridos nuevos
  cubren idiomas, capacidad, reintentos, disponibilidad caducada y resumen móvil.
- Pantallas de 320, 390, 768 y 1440 px; revisión visual del resumen a 390 px.
- El modo `LEGAL_PAGES=published` sigue excluyendo los borradores legales.

El despliegue conserva la base de datos privada y una versión anterior para
volver atrás; se comprueban sus datos y copias mediante la API autenticada,
sin abrir SQLite por SSH/NFS ni enviar correos de prueba a huéspedes.
